# 实验过程中遇到的问题、解决与反思（蔡贸俊）

## 问题与解决
1. GmSSL 安装后库不可用：cmake --install 后 libgmssl.so 位于 /usr/local/lib 且不在 ldconfig 缓存，链接报 cannot find -lgmssl、运行报 cannot open shared object。解决：echo /usr/local/lib > /etc/ld.so.conf.d/gmssl.conf && ldconfig，Makefile 同时加 -L 与 -Wl,-rpath。
2. GmSSL CLI 语法与 OpenSSL 差异大：rand 用 -outlen 指定长度；sm4_cbc 对非 16 倍数明文必须显式 -pkcs7_padding（否则报 input length must be multiple of 16 bytes）；sm3_hmac 密钥至少 12 字节（8 字节报 key should be at least 24 digits）；sm2verify 公钥参数是 -pubkey（误用 -pkey 报错）。解决：逐个查 gmssl <cmd> 的 usage 后修正。
3. openssl dgst 不接受 -in 参数：误用报 Can only sign or verify one file。解决：待签名/验签文件用位置参数给出。
4. OpenSSL C API 两个坑：① EC 类型密钥挂 SM2 曲线不会走 SM2 算法路径（签名失败），必须 EVP_PKEY_CTX_new_from_name(NULL, "SM2") 生成 SM2 类型密钥；② EVP_DigestSignFinal / EVP_PKEY_encrypt 的 size_t 长度参数是 in/out 参数，调用前必须置缓冲区大小，传 0 直接失败。
5. GmSSL C API 摘要收尾函数名为 sm3_finish，误用 sm3_final 导致隐式声明与 undefined reference。
6. 队友命令版信封未传 IV：全 0 IV 解密首块乱码、第二块填充合法，判断密钥与模式正确而 IV 缺失；利用已知明文（对方学号姓名）由 CBC 性质 IV = D(K,C1) xor P1 恢复出 IV=a7954e288e1915d38241b1452534149c 后解密成功。
7. 双人并行推送多次触发 non-fast-forward 拒绝：均以 git pull --rebase 解决后重推，未丢失提交。

## 反思
1. 协议设计：数字信封只约定 C||KC||S1 是不够的，IV 等参数必须显式传递或固定；本次靠已知明文恢复 IV 属于补救，后续已与队友约定 iv.bin 随信封提交或 IV 固定全 0。
2. 过程证据：完整命令+真实输出的文本记录与 git 提交时间线比截图更可靠、可核对；交叉验证（OpenSSL 与 GmSSL 的 SM3/HMAC 逐字节一致）是算法正确性最直接的证据。
3. 协作工程：共享仓库即共享文档的模式运行良好（公钥、信封、留言全部走 git），但应约定编译产物不入仓库、记录文件及时填写，避免"commit 说成功、记录仍待填"的脱节。
4. 效率：验证性实验的难点不在算法而在环境与接口细节（库路径、参数格式、密钥类型），先查 usage/头文件再动手可少走弯路。
